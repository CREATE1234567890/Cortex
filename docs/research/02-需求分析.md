# Cortex — 个人知识库问答 Agent 需求规格说明

> 调研方向：需求分析（产品定位 / 用户故事 / 功能与非功能需求 / MVP 范围）
> 版本 v0.1（2026-10-16）｜定位：深度科研研究助手｜本文档可直接作为技术架构设计输入

---

## 1. 产品定位与目标

**一句话定位**：Cortex 是一个面向个人科研工作者的、以"页码级可溯源引用"为核心承诺的个人文献库问答与研究 Agent。

**产品愿景**：让研究者把机械性的文献劳动（找证据、做对比、写初稿综述）交给可信的 AI，自己只做判断与创造。信任是第一原则：**任何一句话都可以点回去看到原文出处；找不到证据时明确说"不知道"，而不是编造**。

**成功指标（可量化）**：

| 指标 | 目标值 | 度量方式 |
|---|---|---|
| 引用正确率 | ≥95%（引用指向正确论文且页码含支撑证据） | 自建评测集（≥200 题）+ 抽样人工复核 |
| 幻觉率 | 无证据支撑的陈述占比 ≤2%；有据可答时拒答率 ≤5% | 评测集自动标注 + 人工抽检 |
| 简单问答首 token | ≤3s（P95）；端到端 ≤15s | 埋点监控 |
| 检索质量 | 证据 Recall@20 ≥0.9 | 评测集 |
| 深度任务 | 千字综述生成 ≤10 min（异步，含进度反馈） | 任务日志 |
| 规模能力 | 10,000 篇 PDF 入库后检索延迟不劣化 | 压测 |
| 成本 | 轻度用户（日均 20 次问答 + 2 次综述）API 成本 ≤ ¥30/月 | 成本面板 |
| 留存 | 月活跃用户周问答 ≥10 次（验证真实使用） | 使用统计 |

## 2. 用户故事与核心场景

**US-01 批量入库**：作为研究生，我想把文件夹里 200 篇 PDF 一次性拖入，元数据（标题/作者/年份/期刊/DOI）自动补全并去重，以便不花时间手工整理。
验收：批量导入中断可续传；元数据补全准确率 ≥90%；重复文件自动识别（DOI/标题模糊匹配）并提示合并。

**US-02 Zotero 同步**：作为 Zotero 老用户，我想一键授权同步我的文献库（含 collection 结构与附件 PDF），以便 Cortex 与我现有工作流无缝衔接。
验收：首次同步 5000 条目 ≤30 min；之后增量同步 ≤5 min；Zotero 中的删除/移动正确反映。

**US-03 可溯源问答**：作为博士生，我想问"X 方法在数据集 Y 上的表现如何"，获得带引用的答案，点击引用号跳到 PDF 对应页并高亮原文，以便 10 秒内核实。
验收：每个事实性句子至少 1 个引用；点击后 ≤2s 打开原文页并高亮证据段落；引用与陈述错位率 ≤5%。

**US-04 诚实拒答**：作为科研人员，当文献库里没有证据时，我希望系统明确回答"库中未找到相关证据"并说明检索了什么，以便绝不被幻觉误导。
验收：在无证据测试集上，编造答案率 ≤2%；拒答时给出已检索的关键词/范围。

**US-05 PDF 内找证据**：作为研究生，我想问"这篇论文在哪一节讨论了消融实验"，获得章节定位与原文摘录，以便跳过通读。
验收：定位到章节级；摘录含页码；支持在原文视图中连续浏览上下文。

**US-06 综述生成**：作为博士生，我想输入主题"LLM 推理加速"，生成一份分主题组织、每个论断带引用、结尾附参考文献表的综述初稿，以便从 2 天缩到 1 小时。
验收：综述覆盖库中 ≥90% 高相关文献（按专家标注）；每段含引用；输出 Markdown + 参考文献列表；生成过程展示"检索→证据收集→综合"进度。

**US-07 跨论文方法对比**：作为科研人员，我想选定 10 篇论文，让 Agent 抽取"方法名/骨干架构/数据集/指标/核心创新"生成结构化对比表（类 Elicit），以便替代手工 Excel。
验收：每格单元格可点击溯源到原文位置；抽取字段准确率 ≥90%；表格可导出 CSV。

**US-08 公式/表格问答**：作为博士生，我想问"论文 A 中公式 (3) 的损失函数各项含义"，获得公式上下文解释及所在页定位，以便理解难读的数学部分。
验收：公式所在页正确；解释引用原文上下文；表格数据可被问答引用且行列对应正确。

**US-09 笔记联动**：作为研究生，我在阅读时写的笔记能与文献互相关联，问答时 Agent 同时检索笔记和文献并区分来源，以便笔记不再是孤岛。
验收：笔记可关联到文献任意位置；问答结果中笔记引用以不同样式标注；笔记内容入索引。

**US-10 主题追踪**：作为科研人员，我想订阅"graph neural network + drug discovery"主题，定期自动抓取 arXiv 新论文、摘要入库并推送"与你库里 X 篇文献相关"的周报，以便不漏新工作。
验收：周报按相关性排序并说明推荐理由；每条含摘要与入库按钮；误报率可由用户反馈调低。

**US-11 报告导出**：作为博士生，我想把问答与综述导出为 Markdown/LaTeX（含 BibTeX 参考文献表），以便直接用于开题报告写作。
验收：导出保留全部引用且引用编号正确重排；BibTeX 字段完整率 ≥95%；支持 Word 导出（V1）。

## 3. 功能需求清单

优先级定义：**P0 = MVP 必须**（缺此不可用）；P1 = V1 竞争力项；P2 = 增强。P0 判定理由统一为：直接影响"可信"与"能问出第一个答案"这两条底线。

### 3.1 知识库管理（KB）

| 编号 | 优先级 | 需求 | 验收要点 |
|---|---|---|---|
| FR-KB-01 | P0 | PDF 批量导入、进度展示、失败重试 | 200 篇导入无卡死；失败清单可见 |
| FR-KB-02 | P0 | 元数据自动补全（DOI/CrossRef/Semantic Scholar） | 准确率 ≥90%，可手工修正 |
| FR-KB-03 | P0 | 重复检测与合并 | DOI+标题模糊匹配 |
| FR-KB-04 | P0 | Zotero 只读同步（条目+PDF 附件+collection） | 增量同步；同步状态可视化 |
| FR-KB-05 | P1 | Zotero 双向同步（笔记/标签回写） | 冲突提示 |
| FR-KB-06 | P1 | 集合/标签/年份/作者多维组织与过滤 | 过滤后检索生效 |
| FR-KB-07 | P1 | arXiv/RSS 订阅抓取入库 | 主题追踪数据源 |
| FR-KB-08 | P2 | 非 PDF 格式（EPUB/网页/图片笔记） | — |

### 3.2 文档解析（DP）

| 编号 | 优先级 | 需求 | 验收要点 |
|---|---|---|---|
| FR-DP-01 | P0 | PDF 版面解析：正文、双栏、标题层级、页码映射 | 解析后文本保留页码，页码引用的根基 |
| FR-DP-02 | P0 | 表格识别与结构化提取 | 行列还原正确率 ≥85% |
| FR-DP-03 | P0 | 分块策略：语义分块 + 保留页码/章节元数据 | 块大小 300–800 token 可配置 |
| FR-DP-04 | P1 | 公式识别（LaTeX 化）与图表标题抽取 | 公式可检索、可解释 |
| FR-DP-05 | P1 | 扫描件 OCR 兜底 | 检测无文本层 PDF 自动 OCR |
| FR-DP-06 | P1 | 增量解析：仅解析新增/变更文档 | 重复导入不重算 |
| FR-DP-07 | P2 | 图表内容理解（图片 caption + 图内数据） | — |

### 3.3 索引与检索（IR）

| 编号 | 优先级 | 需求 | 验收要点 |
|---|---|---|---|
| FR-IR-01 | P0 | 混合检索：向量 + BM25 关键词，融合排序 | Recall@20 ≥0.9 |
| FR-IR-02 | P0 | 元数据过滤（年份/作者/集合） | 过滤+检索组合可用 |
| FR-IR-03 | P0 | 重排序（cross-encoder reranker） | 证据排序质量提升可测 |
| FR-IR-04 | P1 | 引用图扩展：命中论文的参考文献/被引纳入候选 | 支撑综述覆盖度指标 |
| FR-IR-05 | P1 | 查询改写与多路检索（HyDE/子问题分解） | 复杂问题召回提升 |

| FR-IR-07 | P2 | 万级文档 ANN 索引优化与分层缓存 | 10k 文档检索 <500ms |

## 4. 非功能需求

**性能**：向量+关键词混合检索 <500ms（万级文档，P95）；简单问答首 token ≤3s、端到端 ≤15s；深度任务异步化，10 分钟量级任务必须有进度流与可取消；解析吞吐 ≥20 页/s（本地解析）。

**准确性**：引用正确率 ≥95% 为不可妥协指标；幻觉控制采用四层策略——① 证据先行（解耦架构，答案只能引用已收集证据）；② 拒答优先（无证据不出答案）；③ 生成后引用验证器复核；④ 评测集回归护栏（FR-SM-04）。参考：PaperQA2 证明该范式在科研 QA 上可超人类专家水平（LitQA2 等基准），2025 年 ResearchQA 等基准也表明引用锚定（citation-grounded）生成已是成熟可行的工程路径。

**隐私与安全**：默认本地优先——文档、索引、笔记、对话记录全部本地存储；仅 LLM 推理调用可选云端 API，且支持全本地模式（Ollama/vLLM）。发送到云端的内容仅限检索出的文本块，不上传原始 PDF 全文（除非用户显式要求）；API Key 加密存储；明确提示云端模式的隐私边界，由用户自担选择。

**可扩展性**：单库支持 ≥10,000 篇 PDF / 约 10M 文本块；索引构建可断点续传；架构上检索层与生成层解耦，模型可替换。

**可用性**：本地应用形态（Web UI），核心操作（导入→提问→点引用）3 步内可达；长任务不打断交互；数据格式开放（Markdown/SQLite/原始 PDF），随时可迁移。

**成本约束**：个人可承受，目标轻度用户 ≤¥30/月、重度用户 ≤¥150/月。手段：嵌入与重排用小模型本地化、生成按任务复杂度分层路由（简单问答用轻量模型，深度研究才用旗舰模型）、证据与答案缓存、Agent 步数预算上限。

## 5. MVP 范围界定（4 周 / 8 周 / 12 周）

**MVP（P0，约 4 周）包含**：PDF 批量导入 + 元数据补全去重（FR-KB-01~03）、Zotero 只读同步（FR-KB-04）、版面/表格解析与分块（FR-DP-01~03）、混合检索+重排+过滤（FR-IR-01~03）、带句级引用的流式问答 + 拒答 + 多轮（FR-QA-01~04）、解耦式 Agent 循环与综述生成（FR-RA-01~03）、引用跳页高亮 + 引用验证器（FR-CT-01~02）、Markdown 笔记（FR-NW-01）、模型配置与本地存储（FR-SM-01~02）。

**MVP 明确不包含（Out of Scope）**：Zotero 双向同步、arXiv 订阅与主题追踪、结构化抽取表、研究报告生成、公式 LaTeX 化理解、扫描件 OCR、LaTeX/Word 导出、双向笔记链接、成本面板、引用网络可视化、多用户与协作、移动端。

**V1（约 8 周，P1）**：抽取表（FR-RA-04）、主题追踪周报（FR-RA-05/FR-KB-07）、报告生成（FR-RA-06）、公式与 OCR 解析（FR-DP-04~05）、引用图扩展与查询改写（FR-IR-04~05）、范围限定问答（FR-QA-05）、BibTeX 导出（FR-CT-03）、成本面板与评测回归（FR-SM-03~04）、划词摘录笔记（FR-NW-02~03）。

**V2（约 12 周，P2+增强）**：图表内容理解（FR-DP-07）、引用网络可视化（FR-CT-04）、双向笔记链接与知识图谱（FR-NW-04）、备份迁移（FR-SM-05）、万级文档深度优化（FR-IR-07）、非 PDF 格式支持（FR-KB-08）。

迭代原则：V1 全部投向"深度研究"差异化能力（对比表、追踪、报告）；V2 投向生态与规模。每个版本发布前必须通过评测集回归（引用正确率 ≥95% 不回退）。

## 6. 关键风险与假设

**R1 幻觉引用摧毁信任（产品最高风险）**：科研用户幻觉容忍度≈0，一次编造引用即可能永久流失。缓解：解耦架构+拒答+引用验证器三层防线；引用默认展示原文摘录而非仅编号；把引用正确率做成发布门禁。假设校验方式：评测集持续扩充 + 用户一键"举报错误引用"通道。

**R2 PDF 解析质量瓶颈**：双栏、公式、复杂表格解析错误会沿链路放大到检索与引用。缓解：选用成熟解析方案（MinerU 级），解析失败可见可重试；表格/公式单独验收；页码映射做端到端测试。

**R3 深度 Agent 成本与失控循环**：多轮检索综述任务可能烧穿预算或死循环。缓解：步数/Token 预算上限（FR-RA-07）、可取消、成本面板、分层模型路由。

**R4 万级文档性能退化**：朴素向量检索在 10M 块下延迟与召回双降。缓解：MVP 即引入 ANN + 重排架构；V2 做分层缓存与元数据剪枝；以压测（10k 篇）为验收门槛。

**R5 外部依赖风险**：Zotero API 限流、LLM 提供商涨价/降智、解析库维护停滞。缓解：抽象适配层，提供商可配置可替换；全本地模式保底。

**R6 范围蔓延（单人/小团队开发）**：深度研究功能诱惑多。缓解：以本文 MVP 边界为契约，P1 项一律不得挤入 MVP。

**技术假设**：① 用户文献以文本型 PDF 为主（扫描件 <10%）；② 用户可接受云端 LLM API 或自备本地模型；③ Zotero 是主要文献管理入口（否则退化为手动导入路径，MVP 已覆盖）；④ 主流模型的长上下文与指令遵循能力足以支撑页码级引用输出，且引用锚定生成已是可工程化验证的成熟范式（PaperQA2、ResearchQA 等公开结果）。
