# Cortex 竞品调研报告：个人知识库问答 Agent（深度科研研究助手）

> 调研方向：应用调研（竞品 / 同类产品 / 开源项目）
> 调研时间：2026-10，基于 WebSearch 实时检索，信息时效以 2025 全年～2026 年初为主，关键节点已标注。
> Cortex 定位假设：面向个人研究者的**本地化文献库 + 深度科研问答 + 引用可溯源**的 Agent 产品。

---

## 一、A 类：通用 RAG 知识库产品/开源项目

### 1. RAGFlow（infiniflow）★ 最值得对标的开源项目
- **定位**：以"深度文档理解"为核心的开源 RAG 引擎。
- **核心功能**：DeepDoc 解析（OCR/TSR 表格识别/版面分析三个视觉模型）、按模板分块、带引用的证据式问答、GraphRAG、检索测试调优界面。
- **技术与部署**：Docker/源码，本地部署成熟；**v0.20（2025-08）引入统一 Agent 引擎 + Multi-Agent + Deep Research**；v0.23（2025-12）加入 Memory、Ingestion Pipeline；**v1.0-rc 用 Go 重写**以降低资源占用（[Release notes](https://ragflow.io/docs/release_notes)、[博客](https://ragflow.io/blog/ragflow-0.20.0-multi-agent-deep-research)）。
- **亮点**：文档解析深度业界领先；引用与原文块绑定，天然可溯源。
- **短板**：科研 PDF 的公式/跨栏解析仍不如专用模型；Agent/深度研究能力刚起步；面向企业通用文档而非文献元数据。
- **对 Cortex 的启示**：① "解析质量决定 RAG 上限"已被验证，应把文档解析作为第一优先级模块；② chunk 级引用是好的溯源起点，但科研场景需升级为"文献+页码/图表"粒度。

### 2. Dify
- **定位**：最完整的开源 LLM 应用开发平台（BaaS + Workflow + Agent + 知识库）。
- **核心功能**：可视化编排、模型管理、RAG 知识库、多应用形态发布。2025 年迭代至 2.x，插件/MCP 生态扩展快。
- **技术与部署**：Docker 自托管 + 云服务双形态；许可证为修改版 Apache 2.0（多租户/品牌限制需注意）。
- **亮点**：功能最全、生态最大；社区对比中公认"综合第一"（[对比笔记](https://hustyichi.github.io/2024/07/08/compare)）。
- **短板**：内置 RAG 检索质量平庸（简单分块），深度问答需外挂 RAGFlow 等检索后端；对科研文档无特殊处理。
- **启示**：编排层不必重复造轮子——Cortex 的 Agent 编排可借鉴其工作流抽象，但检索层必须自研加深。

### 3. FastGPT（labring）
- **定位**：开箱即用的"知识库问答 + 可视化工作流"平台（[GitHub](https://github.com/labring/fastgpt)）。
- **核心功能**：QA 对导入增强检索、Flow 节点编排、多模型接入。
- **技术与部署**：TypeScript/Next.js + MongoDB/PGVector，Docker 部署简单，Apache 2.0。
- **亮点**：上手最快，中文生态好；"QA 对"分块思路对文献摘要场景有参考价值。
- **短板**：深度文档解析弱；复杂 Agent 能力有限。
- **启示**：利用文献元数据（标题/作者/摘要）生成"QA 对"作为索引增强，是低成本高收益的检索技巧。

### 4. AnythingLLM
- **定位**：最容易上手的全栈本地知识库聊天应用。
- **核心功能**：Workspace 文档集合、内置 LanceDB 向量库、桌面端一键部署、内置 Agent（网页浏览等）。
- **技术与部署**：桌面 App（Win/Mac/Linux）+ Docker 服务端，全程本地。
- **亮点**：个人/小团队零门槛；隐私友好。
- **短板**：解析与检索管线较浅，引用粒度粗（常只给文档名）；无科研语义。
- **启示**：验证了"个人本地知识库"需求真实存在；Cortex 应在此基础上做深而非做浅。

### 5. Open WebUI
- **定位**：自托管 ChatGPT 风格多用户 UI，RAG 是其工作台功能之一。
- **核心功能**：**v0.6（2025-03）将 Documents 重构为 Workspace → Knowledge**，支持 Focused Retrieval(RAG)/Full Context 两种模式、混合搜索、外接 reranker、外接向量库，2025 下半年引入 Docling 解析（[官方文档](https://docs.openwebui.com/features/workspace/knowledge)）。
- **亮点**：社区庞大、迭代极快；多用户权限完善。
- **短板**：RAG 配置项繁多、效果依赖用户调参；引用呈现基本是文本片段，无结构化溯源。
- **启示**："Knowledge 集合绑定到模型/会话"的交互模式值得沿用；解析层接 Docling 说明解析与前端解耦是趋势。

### 6. Cherry Studio
- **定位**：桌面级 AI 生产力客户端（多模型聚合 + 知识库 + MCP）。
- **核心功能**：60+ 模型供应商、本地/云端知识库挂载到对话、MCP 工具、2.0 版引入 Agent 工作流（[GitHub](https://github.com/cherryhq/cherry-studio)）。
- **亮点**：桌面体验好，本地模型（Ollama）配合顺滑。
- **短板**：知识库仍是"上传-PDF 切片-向量检索"的浅管线；无深度研究能力。
- **启示**：个人工具形态上"客户端 + 用户自带 API Key"是可持续模式；Cortex 可做 Web 自托管 + 桌面封装。

### 7. Khoj
- **定位**：开源"个人 AI 第二大脑"，最接近 Cortex 的"个人知识库问答"形态。
- **核心功能**：索引 Markdown/Org/PDF/Notion/GitHub，语义搜索、带引用聊天、自定义 Agent、定时自动化研究摘要（[GitHub](https://github.com/khoj-ai/khoj)）。
- **亮点**：自托管 + 云服务双形态；自动化"定期研究"是独特功能。
- **短板**：面向通用笔记而非学术文献；深度检索与引用严谨性一般。
- **启示**："自动化定期研究任务"可成为 Cortex 的差异化功能（如每周文献追踪）。

### 8. Obsidian 生态：Copilot for Obsidian / Smart Connections
- **定位**：笔记库内 AI：Copilot 全能对话助手（Vault QA + Agents），Smart Connections 本地嵌入做"被动语义关联"（[obsidiancopilot.com](https://www.obsidiancopilot.com/en)、[GitHub](https://github.com/brianpetro/obsidian-smart-connections)）。
- **亮点**：本地/隐私优先；Smart Connections 的"无提示自动召回相关内容"体验独特。
- **短板**：受限于插件沙箱，无法做重型解析与多跳研究。
- **启示**："检索结果主动推送相关文献"可作为 Cortex 的轻量功能；与 Obsidian/Zotero 的文件级集成胜过自建孤岛。

### 9. Notion AI
- **定位**：SaaS 工作区 AI（闭源）。**2025-05 发布 Enterprise Search、Research Mode、AI 会议笔记**，Business 档 $20/人/月含无限 AI（[发布说明](https://www.notion.com/releases/2025-05-13)、[定价](https://www.notion.com/pricing)）。
- **启示**：大厂把"搜索 + 问答 + Research 模式"做成标配，验证了方向；但其数据在云端且不懂科研文献，本地化科研场景不受威胁。

## 二、B 类：科研垂直 AI 工具

### 10. Elicit ★ 科研工作流标杆
- **定位**：自动化文献综述的 AI 研究助手（[elicit.com](https://elicit.com)）。
- **核心功能**：论文发现、结构化数据抽取成表、发现综合；主打系统综述的筛选与数据抽取环节（宣称省时最多 80%）。
- **技术与部署**：闭源 SaaS；Pro $49/月。
- **亮点**：2025 年有同行评议研究（*Research Synthesis Methods*）验证其数据抽取可用性、但强调需人工监督（[论文](https://www.cambridge.org/core/journals/research-synthesis-methods/article/using-elicit-ai-research-assistant-for-data-extraction-in-systematic-reviews-a-feasibility-study-across-environmental-and-life-sciences/C97DAEC70C3173A260F0B12E729E7250)）。
- **短板**：基于公共语料（1.25 亿论文），**无法以用户个人文献库为中心**；闭源、按 credits 收费。
- **启示**：① "结构化抽取表格（PICO 式列）"是综述场景刚需，Cortex 应内置"跨文献对比表"；② 抽取结果需可人工核对——每格都要能跳回原文。

### 11. Consensus / Scite.ai / SciSpace（简评）
- **Consensus**：对"是/否型研究问题"做跨论文证据综合问答，含 Consensus Meter。
- **Scite.ai**：**Smart Citations** 将引用分为 supporting/contrasting/neutral，引用情报独一档（~$12/月）。→ **启示**："支持/反对证据分类"是高价值引用语义，Cortex 可用 LLM 在个人库内低成本复现。
- **SciSpace**：2.8 亿论文 + Deep Review 综述 agent + 写作辅助，覆盖面最广但深度与准确性口碑一般。

### 12. PaperQA2（FutureHouse）★ 引用机制的黄金标准
- **定位**：高精度科研文献 RAG Agent（开源，[GitHub](https://github.com/future-house/paper-qa)）。
- **核心功能**：工具化 agentic RAG——paper search → gather evidence → gen answer 三工具自由编排，可探索引用图、迭代修正检索参数；答案内嵌带页码的文内引用。
- **时效**：**2025-03 在 RAG-QA Arena 科学基准上达到 SOTA，超出最强人类参赛者 12.4%**（[FutureHouse 公告](https://www.futurehouse.org/research-announcements/paperqa2-achieves-sota-performance-on-rag-qa-arena-science-benchmark)）。
- **短板**：工程库而非产品，无 UI/文献管理；token 消耗大；默认面向语料目录而非 Zotero 式库。
- **启示**：① "证据收集与答案生成解耦 + 引用必须在证据池内"是其准确率来源，Cortex 的核心循环应照此设计；② 引用图探索（顺藤摸瓜找文献）对个人库同样有效。

### 13. Ai2 Asta / OpenScholar
- **定位**：AI2 的"可信科研 Agent 生态"，**2025-08-26 正式发布**，OpenScholar/Paper Finder 能力并入（[官方博客](https://allenai.org/blog/asta)）。
- **核心功能**：Find papers / Generate reports / Analyze data / Generate theories 四大能力，与 Semantic Scholar 深度整合；配套 ASTA-Bench 评测与开源模型、开发者资源。
- **亮点**：主打透明、可复现、可溯源，代表"可信科研 AI"路线。
- **短板**：仍以公共学术语料为中心；非个人文献库管理工具。
- **启示**："可信 > 聪明"是科研 AI 的公信力根基——Cortex 每个结论都应给出可点击的证据链。

### 14. gpt-researcher / LangChain open_deep_research（开源深度研究 Agent）
- **定位**：自主深度研究 agent，**2025 年推出 Deep Research 递归研究模式**（广度×深度迭代检索→报告），被称为开源版 OpenAI Deep Research（[GitHub](https://github.com/assafelovic/gpt-researcher)，30k+ stars）；[LangChain 版](https://github.com/langchain-ai/open_deep_research) 2025-08 更新并给出 Deep Research Bench 成绩。
- **亮点**：plan→search→synthesize 的迭代循环 + 内联引用报告；架构清晰易改造。
- **短板**：面向开放网络检索，不索引个人文献库；引用为 URL 级，无页码级定位。
- **启示**：其"迭代检索-反思-补搜"循环可直接移植到个人库 + Web 混合检索场景。

### 15. STORM / Co-STORM（Stanford OVAL）
- **定位**：从零生成维基百科式带引用长文；Co-STORM 支持用户以对话方式协作策展（[GitHub](https://github.com/stanford-oval/storm)）。
- **亮点**：多视角提问（perspective-guided question asking）→ 大纲 → 带引用成文的三段式，是综述生成的经典范式。
- **短板**：依赖网络搜索；长文引用密度高但逐句溯源到 PDF 页面的能力弱。
- **启示**：多视角大纲生成适合 Cortex 的"综述/主题报告"模式。

### 16. Zotero 生态：PapersGPT / Zotero GPT / Beaver（简评）
- **PapersGPT**（源自 zotero-gpt）：Zotero 内直接对话 PDF、多篇交叉分析、AutoPilot 批处理 100+ 篇，宣称"把孤立 PDF 变成高精度知识库"（[官网](https://www.papersgpt.com/en)、[GitHub](https://github.com/papersgpt/papersgpt-for-zotero)）；另有 Beaver 等。
- **短板**：插件形态受限于 Zotero 沙箱，RAG 浅、无跨库深度研究、无独立知识沉淀层。
- **启示**：**Zotero 是个人文献库事实标准，Cortex 应以"连接 Zotero（元数据+PDF+标注）为第一公民数据源"**，而非要求用户重新上传。

## 三、C 类：RAG/Agent 技术框架（简评）

- **LlamaIndex**：数据摄取/索引最强、API 最简，基准延迟 ~6ms；适合做 Cortex 检索层基座（[对比](https://aimultiple.com/rag-frameworks)）。
- **LangChain/LangGraph**：LangGraph 以图状态机编排 Agent 是当前主流（延迟 ~14ms 稍高）；适合复杂多步研究循环。
- **Haystack 2.x**：生产级低延迟（~5.9ms），管线组合清晰。
- **GraphRAG（微软）**：社区摘要解决全局性问题，但索引昂贵（逐 chunk LLM 抽取 30+ 分钟）。
- **LightRAG**：异步图抽取（~8 分钟）+ 图向量混合检索，性价比最高的图 RAG。
- **HippoRAG 2**（NeurIPS）：受海马体记忆启发，OpenIE 图 + Personalized PageRank，多跳推理与单跳兼顾，基准优于 GraphRAG/LightRAG（[GitHub](https://github.com/osu-nlp-group/HippoRAG)）。
- **KAG（蚂蚁/OpenSPG）**：真知识图谱 + 逻辑形式引导推理，面向企业级强推理场景，工程复杂度高。
- **对 Cortex 的意义**：跨文献概念关联（"方法 A 与方法 B 的关系"）是向量检索盲区，**HippoRAG 2 / LightRAG 的轻量图索引**是务实选择。

## 四、D 类：文档解析开源项目（简评）

学术 PDF 解析 2025 年进入"小模型 VLM 时代"，主战场是 [OmniDocBench（CVPR 2025）](https://github.com/opendatalab/OmniDocBench)：
- **MinerU 2.5**（1.2B）：OmniDocBench 综合领先，公式/表格强，中文好（[GitHub](https://github.com/opendatalab/MinerU)）。
- **PaddleOCR-VL 1.5**（0.9B）：OmniDocBench v1.5 得分 94.5%，宣称超 GPT-4o，多语言强（[论文](https://arxiv.org/html/2510.14528v1)）。
- **olmOCR 2**（AI2）：olmOCR-bench 82.4，表格 +12pt、多栏 +6pt（[博客](https://allenai.org/blog/olmocr)）。
- **Docling**（IBM/Granite-Docling）：工程化好（Open WebUI 内置），表格结构强；**Marker**：速度快、Markdown 干净；**Nougat**（Meta）：学术解析先驱但维护停滞、有幻觉问题，已被取代；**PaddleOCR**：传统管线稳定，VL 版上位。
- **结论**：Cortex 解析层首选 **MinerU 或 PaddleOCR-VL**（公式/表格/中文），Docling 做通用文档兜底。

## 六、市场空白与差异化机会

1. **个人文献库与科研问答割裂**：Elicit/Asta/Consensus 以公共语料为中心，不能"只在我的 500 篇文献里答 + 需要时扩展到全网"；通用 RAG 平台反之，不懂文献元数据（作者/年份/期刊/引用网络）。
2. **引用溯源粒度不足**：通用产品引用到 chunk/URL；科研需要**文献级 → 页码 → 图表/公式定位**的三级溯源，仅 PaperQA2 达标但无产品化 UI。
3. **深度研究不落库**：gpt-researcher/STORM 的研究报告无法沉淀回个人知识库形成累积资产；Khoj 有自动化但无科研深度。
4. **解析质量与语义完整性矛盾**：通用平台的朴素分块切断论文的章节/图表逻辑；专用解析模型（MinerU 等）尚未被知识库产品广泛产品化。
5. **隐私与成本的中间态缺失**：纯本地（AnythingLLM）太浅，纯 SaaS（Elicit）贵且数据外流；"本地库索引 + 可选云端大模型"的混合形态是空白。

**交叉点定位**：以 Zotero 个人文献库为中心 + 科研级 PDF 解析 + 页码级可验证引用 + 迭代式深度研究 + 本地优先——四者兼备的成熟产品目前不存在。

## 七、对 Cortex 的策略建议

1. **总体路线：自研产品层 + 开源组件层，不做大平台**。解析层直接集成 MinerU/PaddleOCR-VL（或借鉴 RAGFlow DeepDoc 的 OCR+TSR+版面三模型管线）；检索索引用 LlamaIndex/Haystack 之一；Agent 编排用 LangGraph 或轻量自研——把自研精力集中在**科研语义层**（文献元数据、引用网络、证据抽取）。
2. **借鉴 PaperQA2 的证据闭环**：search → gather evidence → answer 三工具循环，答案仅允许引用证据池内的句子并附页码；这是准确率 SOTA 的核心，工程上可直接读其源码移植。
3. **借鉴 gpt-researcher 的迭代深度研究**：广度×深度的递归"检索-反思-补搜"，扩展为"个人库优先 → 引用图扩链 → 按需 Web 补充"的混合研究模式；报告结构参考 STORM 的多视角大纲。
4. **Zotero 深度集成为第一公民**：读 .bib/sqlite 与 PDF 标注，免重新上传；支持"支持/反对"式引用分类（学 Scite）与 Elicit 式跨文献对比表。
5. **差异化功能**：① 每周文献追踪自动化（学 Khoj）；② HippoRAG 2 式轻量图索引支撑跨文献概念问答；③ 所有结论提供"点击跳转到 PDF 页码/图表"的三级溯源。
